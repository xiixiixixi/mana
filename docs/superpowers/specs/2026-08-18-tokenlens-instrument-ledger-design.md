# Tokenlens「精密仪表账本」界面设计规格

日期：2026-08-18  
状态：已选定视觉方向，待书面确认后进入实施  
覆盖范围：主弹窗、设置页、共享视觉样式与真实渲染验收

## 1. 背景

现有界面已经具备清晰的数据能力：本地用量、各服务配额、剩余比例、刷新时间、配置入口和错误状态均可用。但视觉上仍以重复卡片为主，边框、圆角、英文小字和同权重区块过多，导致信息层级不够清楚，也容易呈现常见的模板化 AI 界面观感。

本次改造采用已选定的 A 方向「精密仪表账本」（Instrument Ledger）：把界面从卡片墙改造成一张连续、严谨、可快速扫读的仪表账本。设计保留项目现有等宽字体与十格配额条，不改变任何数据含义和交互能力。

## 2. 设计目标

### 2.1 核心任务

用户打开主弹窗后，应在几秒内完成三件事：

1. 看清本地今天、近一周和本月的使用量。
2. 找出剩余额度最少或状态异常的服务。
3. 看清每项额度还剩多少、何时重置，并能立即刷新或进入设置。

### 2.2 目标

- 建立明确的阅读顺序：系统状态 → 本地使用 → 最紧急服务 → 其他服务。
- 在 380 像素宽的主弹窗中提高信息密度，同时保持轻松可读。
- 让主弹窗与设置页像同一套产品，而不是两个各自维护的页面。
- 让颜色、线条和动画都表达状态，不做纯装饰。
- 保留 Space Mono 字体及当前配额含义：所有百分比和格条均表示“剩余多少”。

### 2.3 非目标

- 不改变服务端接口、数据结构、刷新策略或账户配置逻辑。
- 不增加新的配额计算方式、费用信息或字母图标。
- 不引入前端框架、组件库、插画、渐变、阴影或玻璃拟态。
- 不重新设计 macOS 菜单栏图标或应用外壳。
- 不为了视觉效果牺牲键盘操作、对比度和减少动画设置。

## 3. 视觉命题

界面是一张实时更新的设备账本，而不是一组悬浮卡片。

视觉语言由四部分组成：

- 连续纸面：页面只有一个主平面，不用容器层层包裹。
- 精确网格：服务名称、额度条、百分比和重置时间按固定列对齐。
- 细线分区：用一像素分隔线建立节奏，不用大圆角卡片制造层次。
- 单一信号色：橙色只标记最紧急额度、错误和主要操作。

### 3.1 避免模板化观感的约束

- 不使用渐变、发光、投影、毛玻璃和大面积品牌色背景。
- 不把每段内容都包进圆角矩形。
- 不用无意义的大标题、编号、徽章和装饰性状态胶囊。
- 不滥用全大写和宽字距；只在极短的系统标签中使用。
- 不用大段灰色说明文案占据首屏。
- 不用循环呼吸、漂浮或扫光动画。

## 4. 设计变量

### 4.1 颜色

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 纸面 | `#F7F7F5` | 页面底色 |
| 数据面 | `#FFFFFF` | 需要与纸面轻微区分的数据带 |
| 主墨色 | `#111111` | 标题、关键数值、主要正文 |
| 石墨灰 | `#6F6F69` | 辅助标签、时间、说明 |
| 发丝线 | `#DCDCD6` | 表格分隔、轨道、输入框边界 |
| 信号橙 | `#FF3B00` | 最紧急状态、错误、主要操作 |

信号橙不得作为大面积背景。正常状态主要依靠主墨色、石墨灰和格条密度表达。

### 4.2 字体与字号

字体族保持项目现状：

```css
font-family: "Space Mono", "SF Mono", Menlo, monospace;
```

建议字号层级：

| 角色 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题 | 14px | 700 | 1.2 |
| 核心数值 | 18px | 700 | 1.1 |
| 服务名称 | 12px | 700 | 1.25 |
| 正文与输入 | 11px | 400 | 1.45 |
| 辅助信息 | 10px | 400 | 1.4 |
| 微型系统标签 | 9px | 700 | 1.3 |

全局不使用超过 18 像素的文字。正文默认不做全大写；英文服务名保持官方拼写。

### 4.3 形状与间距

- 主分隔线：1px。
- 输入框和按钮圆角：最多 3px。
- 状态标记、数据行、配置行：0px 圆角。
- 页面横向留白：16px。
- 大区块垂直间距：16px。
- 行内间距以 4px、8px、12px、16px 为基础。
- 最小可点击高度：28px；图标按钮保持完整焦点框。

## 5. 主弹窗

### 5.1 页面结构

```text
┌──────────────────────────────────────────┐
│ MANA                         刷新  设置  │
│ [ONLINE] 6 个服务             12:46 更新 │
├──────────────────────────────────────────┤
│ LOCAL / 本地使用                         │
│ 今天  128k       近 7 天  742k           │
│ 本月  1.92m      14 天趋势  ▂▃▂▄▅▃▆…    │
├──────────────────────────────────────────┤
│▌Claude Code                              │
│  5 小时额度   ■■■□□□□□□□   32%   2h 18m │
│  周额度       ■■■■■■□□□□   61%   周一    │
├──────────────────────────────────────────┤
│  Codex                                   │
│  5 小时额度   ■■■■■■■□□□   73%   3h 02m │
├──────────────────────────────────────────┤
│  Gemini                                  │
│  日额度       ■■■■■■■■□□   82%   明天    │
└──────────────────────────────────────────┘
```

图中的格条仅表达结构；实际继续使用项目现有十格 CSS 配额条。

### 5.2 顶栏

- 左侧只显示产品名 `MANA`，不增加宣传语。
- 右侧保留刷新与设置操作，使用当前图标或短标签，不使用实心黑色大按钮。
- 操作默认呈墨色；悬停和键盘聚焦时用细橙色下划线或轮廓。
- 顶栏下方为紧凑状态行：左侧状态，右侧最后更新时间。
- 状态使用方括号文本，如 `[ONLINE]`、`[SYNCING]`、`[ERROR]`，不用圆角胶囊。

### 5.3 本地使用数据带

- 本地用量从普通卡片提升为页面顶部的横向数据带。
- 背景可使用数据白 `#FFFFFF`，上下以发丝线收边。
- 今天、近 7 天、本月为三个对齐的数据单元，数值比标签更醒目。
- 14 天趋势保持紧凑，只承担趋势辅助作用，不与核心数值争夺注意力。
- 数据缺失时保留布局，用 `—` 显示，不让页面跳动。

### 5.4 服务账本行

每个服务由“服务标题行 + 一至多条额度行”组成：

- 服务标题位于独立左轨，不使用头像、字母图标和容器背景。
- 额度行采用固定四列：额度名称、十格配额条、剩余百分比、重置时间。
- 百分比始终表示剩余量；列标题或辅助说明只需出现一次，不在每行重复解释。
- 服务之间使用一像素分隔线；同一服务的多条额度不再套小卡片。
- 重置时间使用简短本地语言，例如 `2h 18m` 可在中文界面显示为 `2 小时`，避免冗长句子。
- 服务顺序继续遵从当前数据逻辑，不在这次视觉改造中改变排序规则。

### 5.5 紧急度索引轨

这是整套设计唯一的强识别元素。

- 页面左侧为 2px 的状态轨道，与服务行垂直对应。
- 正常服务不着色，保持透明或发丝线色。
- 当前最紧急的服务使用信号橙短线；错误服务同样使用橙色，但必须同时有文字状态，不能只靠颜色。
- 紧急服务由现有剩余量和错误状态推导，不新增业务接口。
- 若多项同为最低值，只突出第一项，避免形成多条装饰色带。

### 5.6 加载、空白与错误

- 加载时保留完整列结构，格条用低对比度静态占位，不使用闪烁骨架屏。
- 无服务时显示一段简短说明和进入设置的文字按钮。
- 单个服务错误只影响该服务行，展示短错误原因和重试入口，不遮挡其他数据。
- 全局请求失败在状态行显示 `[ERROR]`，页面保留上一次成功数据（若当前逻辑已有缓存）。

## 6. 设置页

### 6.1 页面结构

```text
┌──────────────────────────────────────┐
│ SETTINGS                      完成   │
│ 配置服务连接与显示                   │
├──────────────────────────────────────┤
│ SERVICE         CREDENTIAL      STATE│
├──────────────────────────────────────┤
│ Claude Code     •••••••••••     已连接│
│                 编辑  测试连接        │
├──────────────────────────────────────┤
│ Codex           •••••••••••     已连接│
│                 编辑  测试连接        │
├──────────────────────────────────────┤
│ Gemini          未配置          —    │
│                 添加                  │
└──────────────────────────────────────┘
```

### 6.2 配置账本

- 删除重复的圆角配置卡，改为连续表格。
- 服务名、凭据区、连接状态按固定列对齐。
- 每个服务的现有输入、保存、测试、删除或开关能力全部保留。
- 输入框只有一像素边框和最多 3px 圆角；聚焦时使用橙色边框和清晰焦点环。
- 主要操作使用橙色文字或小面积橙色底；危险操作只在悬停、聚焦或确认阶段突出。
- 说明文字放在对应字段下方，不增加独立提示卡。
- 设置页宽度按现有 360 像素窗口设计，内容不得产生横向滚动。

## 7. 交互与动效

- 刷新开始后，状态文字切换为 `[SYNCING]`，按钮保持可识别的忙碌状态。
- 新数据到达时，只允许配额格和数值做 120–180ms 的淡入或宽度过渡。
- 不使用整个卡片上浮、弹跳、闪光或无限循环动画。
- `prefers-reduced-motion: reduce` 下关闭所有非必要过渡。
- 所有按钮、链接和输入必须有可见的 `:focus-visible` 状态。
- 键盘顺序遵循视觉顺序：刷新 → 设置 → 服务操作 → 页面底部操作。

## 8. 共享样式与运行结构

当前 `design/` 已包含字体和基础视觉变量，但主弹窗、设置页各自维护大段内联样式，导致迁移不完整。实施后按以下结构收敛：

1. `design/tokens.css` 作为颜色、字号、间距、边框和动效变量的唯一来源。
2. `design/mana.css` 作为主弹窗与设置页的共享组件和布局样式来源。
3. `src/client/popover.html` 只保留页面结构和极少量页面专属样式。
4. `src/client/settings.html` 使用同一套共享样式，不再复制视觉变量。
5. `src/server/app.js` 为应用页面提供只读的 `/design` 静态路径。
6. `src-swift/build.sh` 将 `design/` 一并复制到应用资源，确保打包后的 Mana 不依赖仓库工作目录。

共享样式迁移不得改变现有元素标识、事件绑定和接口调用；如结构调整需要改动选择器，必须同步更新脚本并补充行为验证。

## 9. 响应与窗口适配

- 主弹窗以现有约 380px 宽度为第一验收尺寸。
- 设置页以现有约 360px 宽度为第一验收尺寸。
- 320px 宽度下，服务额度行允许重置时间换到下一行，但服务名、格条和百分比仍需同屏可读。
- 长服务名优先截断并提供完整标题提示，不挤压剩余百分比。
- 数字列使用等宽字体的天然对齐能力，并设置稳定列宽，刷新时不产生明显横向跳动。

## 10. 无障碍与内容规则

- 主文字与背景对比度达到 WCAG AA（网页内容无障碍指南 AA 级）要求。
- 橙色状态必须同时配合文字、图形或位置，不单独承担含义。
- 图标按钮保留可读的辅助名称。
- 错误文案使用简短自然语言，不直接向用户展示原始堆栈或接口对象。
- 中文界面优先使用中文标签；官方服务名、产品名和必要技术名词保留原文。
- 不新增营销文案、空泛副标题或解释性长段落。

## 12. 验收标准

### 12.1 视觉

- 主弹窗与设置页不再呈现重复卡片墙。
- 页面没有渐变、投影、大圆角、发光和装饰性动画。
- Space Mono 字体在打包后的真实页面中生效。
- 所有正文不超过 18px，主要信息无需滚动即可快速识别。
- 服务名、格条、剩余比例和重置时间形成稳定列对齐。
- 只有最紧急或错误状态使用橙色状态轨。

### 12.2 行为

- 刷新、进入设置、保存、测试连接及当前已有操作全部可用。
- 所有百分比和十格条继续表示剩余额度。
- 加载、空白、单项错误和全局错误状态均能正确显示。
- 键盘焦点清晰，减少动画设置生效。

### 12.3 工程

- 两个页面共同加载 `design/` 中的视觉变量和共享样式。
- 打包脚本包含 `design/` 资源，安装后的应用可独立运行。
- Swift 构建通过。
- 页面脚本语法检查与现有测试通过。
- 用真实 Mana 窗口或同一服务地址分别验证主弹窗和设置页，不以静态示例页代替运行结果。
- 至少保留主弹窗和设置页各一张最终截图，并检查 380px、360px 和窄宽度下的溢出与焦点状态。

## 13. 完成定义

只有在共享样式落地、应用重新构建、真实运行页面完成桌面级目视检查、现有交互通过验证后，才算完成本次改造。仅修改 `design/` 示例、仅通过构建或仅生成静态截图都不算完成。
